How I build

From problem to live in three moves.

A repeatable way of working that keeps the diff small and the product shipping.

01

Understand the real problem

Trace the whole flow end to end before writing a line. The smallest change in the wrong place is just a second bug.

02

Ship the smallest thing that works

Get it in front of real users fast. Reuse what exists, lean on the platform, and skip abstractions nothing needs yet.

03

Harden & measure

Then add the auth, rate limits, and RLS that matter — and prove the wins with numbers, like the 806→68 KB cut.

On building safe
Security by default

A cybersecurity student who actually ships secure.

Both live products were built with the trust boundary in mind from the first endpoint — not patched afterward.

  • Server-side authorizationEntitlements are checked on the server — the client is never trusted for access.
  • Row-Level SecurityPostgres RLS so every user can only ever read and write their own rows.
  • Signed webhook verificationRazorpay signatures verified before any payment event is acted on.
  • Per-user & per-IP rate limitingEvery public endpoint is throttled against abuse and runaway cost.
  • OAuth / NextAuthGitHub App JWT plus short-lived installation tokens for repo access.
  • Least-privilege secretsScoped tokens, secrets held server-side only, nothing leaked to the bundle.
